# Схемы и типы

Что получается в C++ из схем спеки и как значения разбираются и сериализуются.

## null и nullable

svarg считает `null` отсутствием значения: пришедший `"a": null` — то же, что отсутствие `a`.

- `nullable: true` (OpenAPI 3.0) и `type: [X, "null"]` (3.1) — одно и то же: тип `X`, поле необязательное
  (`std::optional`).
- Свойство `required` и `nullable` одновременно — тоже необязательное поле, но отсутствующее сериализуется
  как `"a": null`: спека требует, чтобы ключ был. Явно отличить «нет поля» от `null` нельзя.

## Обязательные свойства

- Имя из `required`, которого нет в `properties`, — обязательное поле любого значения (тип `any`).
- `required` и `default` — необязательное поле, всегда присутствующее со значением по умолчанию
  (предупреждение при генерации).
- `required` и `readOnly`/`writeOnly` — необязательное поле: тип один для запроса и ответа (предупреждение).

## Лишние свойства объекта

Свойство, не описанное в `properties`:

| `additionalProperties` в спеке | При разборе | В C++ |
|---|---|---|
| не указан | пропускается | — |
| `false` | ошибка | — |
| `true` или `{}` | сохраняется | `svarg_additional_properties` |
| схема | проверяется по схеме и сохраняется | `svarg_additional_properties` |

`--unsetted-additional-properties false` — неуказанный `additionalProperties` как `false`. Не действует на
объект без описанных свойств (без `properties`, только с `required` или со всеми `properties` без схемы): он
только требует наличия полей, и запрет отверг бы любой объект с другими полями.

В `allOf` из объектов `additionalProperties`, указанный в одной части, не отменяется частью, где он не указан.

## Несколько типов

`type: [string, integer]` — `anyOf` этих типов. `object` и `array` среди них (`type: [string, object]`)
— отдельные типы рядом со схемой (для схемы `Multi` в простом режиме имён — `Multi_::_object` и
`Multi_::_array`), с её `properties` и `items`. `type: array` без
`items` — массив любых значений.

## anyOf, oneOf и дискриминатор

- `anyOf` — разбираются все подходящие варианты, нужен хотя бы один.
- `oneOf` — подходить должен ровно один вариант. Значение, подходящее под два (например, объекты, которые
  различаются только необязательными полями), — ошибка.
- С `discriminator` вариант выбирается по значению свойства, остальные не пробуются. Значение — ключ
  `mapping` (`$ref` или имя схемы), для вариантов не из `mapping` — имя их схемы. Нет свойства или
  неизвестное значение — ошибка; значение не объект — разбирается как без дискриминатора. При
  сериализации `oneOf` значение дискриминатора выставляется по типу варианта.
- Если среди вариантов есть схемы без имени (инлайн), дискриминатор не используется (предупреждение): по
  OpenAPI он сопоставляется только с именованными схемами.

## Рекурсия

Поле, тип которого (в том числе через массив или `anyOf`) ссылается на сам объект, хранится в
`svarg::cxx_support::box<T>` — и необязательное, и обязательное.

## Перечисления

- `enum` — структура со значением (`get()`) и списком `values`. У перечисления строк ещё константы
  значений; константа, имя которой совпало с членом структуры или другой константой, получает суффикс `_`
  (`get_`, `values_`).
- `anyOf: [enum строк, string]` — открытое перечисление: строка `value`, известные значения константами,
  `is_known()`.

## Имена

Служебные члены сгенерированных структур начинаются с `svarg_` (`svarg_fields`, `svarg_parse_tag`...):
такие имена в спеке лучше не использовать.

Имена из спеки переводятся в C++ идентификаторы в одном из двух режимов:

- **простой** (`--simple-identifiers true`, по умолчанию) — читаемые имена (`+1` → `_1`). Разные имена могут
  совпасть (`+1` и `-1` в одном объекте), а поле с тем же именем, что и тип (`label label;`), скрывает тип в
  структуре — такой код не компилируется;
- **уникальный** (`--simple-identifiers false`) — имена не совпадают никогда (`+1` → `Zx2b1`, `-1` →
  `Z01`), типы пишутся полными именами (`::api::components::schemas::label`). Нужен для спек вроде GitHub.
