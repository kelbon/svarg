# Генерация

## Запуск

```
svarg -s <папка со спеками> -o <папка для кода> [опции] api.yaml [другие спеки...]
```

Спеки из командной строки ищутся в `-s` (затем в `-I`), `$ref` — относительно файла, в котором записаны.
YAML и JSON, файл может начинаться с `---`, но документ в нём должен быть один.

Опции, влияющие на сгенерированный код:

| Опция | По умолчанию | Что делает |
|---|---|---|
| `--optimize` (`-O2`) | `true` | упрощает схемы перед генерацией (меньше типов) |
| `--simple-identifiers` | `true` | режим C++ имён, см. [схемы](schemas.md#имена) |
| `--unsetted-additional-properties` | `true` | незаданный `additionalProperties`, см. [схемы](schemas.md#лишние-свойства-объекта) |
| `--sources-per-spec N` | `1` | на сколько `.cpp` делится код каждой спеки, см. ниже |
| `--stream-content-type` | | потоковые медиа типы ответов, см. [клиент](client.md#ответы-потоком) |
| `--file-prefix` | | текст в начале каждого заголовка, например `#include` своих кодеков, см. [кодеки](codecs.md) |
| `--ignore-requirements` | | не проверять ограничения и требования схем: меньше кода, неполная проверка |

## Файлы

На спеку `api.yaml` — папка `api/`:

- `server.hpp`, `client.hpp` — сервер и клиент, если в спеке есть операции;
- `operations/<operationId>.hpp` — операции, `schemas/...` — схемы (по одному заголовку на тип), `all_*.hpp` —
  всё вместе;
- `api.cpp` — определения сервера и клиента и (де)сериализации операций. Его нужно скомпилировать и
  слинковать: в заголовках (де)сериализация только объявлена, чтобы не компилироваться в каждом файле
  пользователя.

### Большие спеки

Весь код спеки вроде GitHub или Stripe (тысячи операций и схем) в одном `.cpp` компилируется очень долго и
требует больше 7 ГБ памяти. `--sources-per-spec N` делит его: в `api.cpp` остаются сервер и клиент, а
(де)сериализация операций поровну раскладывается по `api_1.cpp` ... `api_<N-1>.cpp`, которые собираются
параллельно. Создаются все `N` файлов, даже если операций меньше, — набор файлов зависит только от `N`.

## CMake

```cmake
include(${SVARG_SCRIPT_PATH})  # cmake/svarg_generate.cmake

svarg_generate_cxx(
    TARGET               api_generated
    SPECS_DIR            ${CMAKE_CURRENT_SOURCE_DIR}/openapi
    OUT_DIR              ${CMAKE_CURRENT_BINARY_DIR}/generated
    SPECS                api.yaml
    INCLUDE_DIRS         ...         # необязательно, -I
    STREAM_CONTENT_TYPES ...         # необязательно, --stream-content-type
    SOURCES_PER_SPEC     8           # необязательно, --sources-per-spec
)
target_link_libraries(my_app PRIVATE api_generated)
```

Список сгенерированных файлов узнаётся при конфигурации (`svarg --dry-run`), код генерируется при сборке и
перегенерируется при изменении спеки. После изменения опций или обновления svarg нужно заново запустить
`cmake`, а если набор файлов изменился, удалить старую папку с кодом.

## Ошибки

Ошибка в спеке сообщает место JSON указателем: где ошибка, а если она в схеме, на которую ведёт `$ref`, то и
саму схему:

```
api.yaml#/paths/~1items~1{id}/get/200/content/application~1json: in api.yaml#/components/schemas/Item: ...
```

Сомнительное в спеке, что svarg обходит сам, выводится предупреждением `in <файл>#<указатель>. warning: ...`.

## Разработка svarg

Внутренние проверки svarg (`SVARG_ASSERT`) бывают очень дорогими и выключены даже в Debug. Включить —
`SVARG_ENABLE_ASSERTS 1` в `include/svarg/utils/svarg_assert.hpp`. Выключенная проверка не вычисляется, но
компилируется.
